# /deploy — выкатка Mini App

Владелец не программист: пиши по-русски, коротко, в конце — что изменилось для агентов и что сделать ему.
Аргумент (необязательный): `front`, `back` или `all`. Без аргумента определи сам по `git status` / `git diff origin/main`:
изменён `index.html` → фронтенд, изменён `apps-script/` → бэкенд.

Константы (из `CLAUDE.md`):
- `API_URL` = `https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec` — берётся из `index.html`
- `DEPLOYMENT_ID` — часть `API_URL` между `/s/` и `/exec`
- Pages: `https://prmeadm.github.io/grs/`

## 1. Проверки (всегда)

```bash
.claude/skills/deploy/check.sh
```
Любой `✗` — стоп, чини, не выкатывай. Если изменения не закоммичены — покажи владельцу короткое «что меняем» и закоммить
(сообщение по-русски, о сути изменения).

## 2. Бэкенд (если менялся `apps-script/`)

1. Если `Code.gs` менялся по сути, а `APP_VERSION` не поднят относительно того, что отвечает сервер
   (`curl -sL "$API_URL?check=$RANDOM"` → `version`) — подними `APP_VERSION` на 1 и закоммить.
2. Залей код в редактор (рабочее развёртывание это ещё не меняет):
   ```bash
   cd apps-script && npx @google/clasp push -f
   ```
   Если команду заблокировал классификатор прав — не обходи: дай владельцу эту же команду в блоке ```bash``` (кнопка Run)
   и дождись «залил».
   Ошибка «Apps Script API not enabled» → владелец включает его на https://script.google.com/home/usersettings.
3. Если поменялась работа с секретами или листами — попроси владельца запустить `testMessage` (и/или `setup`)
   в редакторе Apps Script **до** шага 4 и дождись результата.
4. Обнови **существующее** развёртывание (URL не меняется). Никогда не делай `clasp deploy` без `-i`:
   ```bash
   npx @google/clasp deploy -i <DEPLOYMENT_ID> -d "vN: кратко что изменилось"
   ```
5. Проверь: `curl -sL "$API_URL?check=$RANDOM"` → `"ok":true` и `"version"` = новому `APP_VERSION`.
   Не совпало — подожди 10 с и повтори; после 3 попыток — сообщи владельцу, ничего не трогай.

## 3. Фронтенд (если менялся `index.html`)

1. Строку `API_URL` не трогай (её проверяет `check.sh`).
2. `git push origin main`.
3. Дождись GitHub Pages (обычно 30–90 с): выбери строку, которая появилась в этом изменении, и жди её
   в `curl -s "https://prmeadm.github.io/grs/?v=$RANDOM"` — проверка каждые 30 с, максимум 5 минут.
4. Telegram кэширует страницу. Возьми последний номер `?v=` из раздела «Последний ?v» в `CLAUDE.md` и попроси владельца:
   @BotFather → `/myapps` → приложение → Edit Web App URL → `https://prmeadm.github.io/grs/?v=<номер+1>`.
   Когда владелец подтвердит — запиши новый номер в `CLAUDE.md` и закоммить. Если номер неизвестен — спроси.

## 4. Порядок, когда меняется и то и другое

Если новый фронтенд зависит от нового бэкенда — сначала бэкенд (раздел 2), потом фронтенд.
Если новый бэкенд ломает старый фронтенд — наоборот, или сделай бэкенд совместимым с обоими.
Сомневаешься — сначала бэкенд, сохраняя старые поля ответа.

## 5. Итог владельцу

3–5 строк: что выкачено (фронтенд/бэкенд, версия), что проверено, что изменилось для агентов,
и что сделать ему (номер `?v=` в BotFather, тестовый заказ, закрыть и открыть Telegram).

## Откат

- Бэкенд: `npx @google/clasp deployments` → найди предыдущую версию → `npx @google/clasp deploy -i <DEPLOYMENT_ID> -V <номер_версии>`.
- Фронтенд: `git revert <коммит> && git push`, затем новый `?v=` в BotFather.

## После переезда на hoster.by

Когда сервер переедет (план — `docs/PEREEZD-hoster-by.md`), добавь сюда раздел выкатки на hoster.by
(rsync/ssh, проверка версии сервера) и поправь разделы 2–3.
