# Переезд Mini App на hoster.by — план и инструкция

Цель: заказ оформляется за 1–2 секунды вместо 5–30, и сервер не «засыпает».
Принцип: всё, что сейчас медленно (приём фото, отправка в группу, запись в таблицу), берёт на себя свой сервер на hoster.by.
Человек ждёт только записи заказа на сервере, остальное делается в фоне уже после ответа «Заказ оформлен».

Обозначения: 👤 — делаешь ты (логины, оплата, панели), 🤖 — делает Claude Code.

---

## 1. Как будет устроено

| Что | Сейчас | После переезда |
|---|---|---|
| Страница Mini App (`index.html`) | GitHub Pages | hoster.by, свой адрес с HTTPS |
| Приём фото | Apps Script → Google Диск, 2–6 с на фото | PHP на hoster.by, обычная загрузка файлом, без перекодирования |
| Оформление заказа | Apps Script, ждём всё сразу | PHP: проверка, номер заказа, ответ сразу; остальное — в фоне |
| Сообщение и фото в группу | Apps Script | PHP напрямую в Telegram Bot API, в фоне |
| Прайс | лист «Прайс» | **без изменений**: правишь в таблице, сервер подтягивает раз в несколько минут |
| Лист «Заказы» | Apps Script пишет строку | **без изменений по виду**: строку пишет тот же Apps Script, но в фоне, по команде сервера |
| Пересчёт суммы при ручной правке | `onEdit` в таблице | без изменений |
| Архив фото | папка на Google Диске | папка на хостинге (ссылка в ячейке «№ заказа») + файлы в группе, см. решение 2 |

Почему таблица остаётся на Google: ты привык править прайс и смотреть заказы там. Apps Script продолжит писать строки,
просто теперь это происходит в фоне и никто его не ждёт. Отдельный «сервисный аккаунт Google» не нужен.

Чем платим: только твоим тарифом hoster.by. Других платных сервисов нет.

---

## 2. Решения, которые нужно принять до начала (👤)

1. **Адрес приложения.** Telegram открывает Mini App только по HTTPS. Нужен домен или поддомен на hoster.by, например
   `app.твойдомен.by` или `zakaz.твойдомен.by`. Если домена нет — его нужно купить (это единственный дополнительный
   расход, порядка десятка рублей в год за `.by`). **Рекомендую поддомен существующего домена.**
2. **Где хранить фото.**
   - **А (рекомендую):** на хостинге, в папке заказа + оригиналы в группе Telegram. Быстро и просто.
     7 ГБ хватит примерно на 1500–2000 фото; старые фото сервер сам удаляет через N дней (N выбираешь ты, например 90).
   - **Б:** как сейчас, на Google Диске. Сервер в фоне копирует туда фото после отправки заказа. Медленнее в фоне,
     но для агента разницы нет. Места на Диске — сколько есть в аккаунте Google.
3. **Тариф.** Сейчас услуга помечена «ТЕСТ». Перед запуском её нужно оплатить, иначе тестовый период закончится и
   приложение перестанет работать.

## 3. Этапы

### Этап 0. Подготовка хостинга (👤, ~20 минут)

1. **Оплатить** тариф «Стандарт» в личном кабинете hoster.by.
2. **Подключить домен/поддомен** к услуге хостинга: Панель управления хостингом → Сайты (Домены) → Добавить
   → указать адрес из решения 1. Если домен на hoster.by — DNS настроится сам; если в другом месте — нужно
   прописать A-запись на IP `87.232.64.97`.
3. **Включить бесплатный SSL** (Let's Encrypt) для этого адреса: в панели раздел SSL → выпустить бесплатный сертификат.
   Проверка: адрес открывается в браузере с замочком.
4. **Выбрать версию PHP 8.2 или новее** для сайта (раздел PHP / Версия PHP).
5. **SSH-доступ для Claude Code** — без передачи пароля в чат:
   - 🤖 создаю на Mac ключ и показываю команду;
   - 👤 запускаешь в терминале одну команду вида `ssh-copy-id -p 22 <логин>@vh97.hoster.by` и **сам** вводишь пароль
     от хостинга (его можно сбросить в кабинете, если не помнишь);
   - после этого Claude Code заходит на сервер по ключу, пароль больше не нужен.
   Если в панели есть раздел «SSH-ключи» — можно вместо команды вставить туда публичный ключ, который я покажу.

**Готово, когда:** адрес открывается по HTTPS, а Claude Code выполнил на сервере `php -v` и увидел 8.2+.

### Этап 1. Проверка хостинга (🤖, ~10 минут)

1. Проверить, что есть всё нужное: `curl` для запросов в Telegram, `openssl`/`hash_hmac` для проверки подписи Telegram,
   лимиты загрузки (`upload_max_filesize`, `post_max_size` — нужно ≥ 25 МБ на фото), максимальное время работы скрипта.
2. Проверить, работает ли «ответить сразу, доработать в фоне» (`fastcgi_finish_request`). Если нет — запасной путь:
   фоновая очередь через cron раз в минуту (hoster.by даёт cron в панели; тогда сообщение в группу будет приходить
   с задержкой до минуты).
3. При необходимости увеличить лимиты через `.user.ini` (без обращения в поддержку).

**Готово, когда:** тестовый PHP-файл принял фото 20 МБ и отправил тестовое сообщение в группу.

### Этап 2. Новый сервер (🤖, основная работа)

Код живёт в этом репозитории, папка `server/`. Секреты — в `config.php` **только на хостинге**, в репозиторий не попадает.

1. `server/api.php` — один вход для приложения:
   - `GET` — прайс. Берётся из кэша на хостинге; раз в 5 минут кэш обновляется из Google-таблицы через Apps Script.
     Правка прайса в таблице доходит до приложения максимум за 5 минут (можно поменять).
   - `POST upload` — приём одного фото обычной загрузкой файла (без base64 — на треть меньше трафика).
     Проверка подписи Telegram, размера и типа файла.
   - `POST order` — проверка подписи, ФИО/дат табличек, цен по прайсу, фото; присвоение номера заказа;
     защита от двойного заказа (`orderKey`, как сейчас). **Сразу отвечает «Заказ №N оформлен»**, затем в фоне:
     1) сообщение в группу (каждое поле с новой строки, как сейчас);
     2) фото файлами без сжатия ответом на сообщение, с подписью услуги и ФИО;
     3) строка в лист «Заказы» через Apps Script;
     4) (решение 2Б) копия фото на Google Диск.
   - Если что-то в фоне не удалось — повтор; если и он не прошёл, сервер пишет в группу «⚠️ Заказ №N: не удалось …»,
     чтобы заказ не потерялся молча.
2. `server/config.php` (только на хостинге): токен бота, ID группы, ссылка на приложение, секрет для Apps Script.
3. Номера заказов продолжают текущую нумерацию: при запуске забираю последний номер из Apps Script.
4. Хранилище: папка с заказами вне публичной части сайта; фото открываются только по длинным случайным ссылкам.
5. Автоочистка: незавершённые загрузки удаляются через сутки, фото старше N дней (решение 2А) — по cron раз в сутки.
6. Журнал ошибок на сервере — чтобы при проблеме я мог посмотреть причину без тебя.

### Этап 3. Изменения в Apps Script (🤖)

1. Новое действие `append`: принимает от сервера готовый заказ (номер, дата, агент, услуги, ФИО/даты, ссылка на фото)
   и пишет строку — формат листа «Заказы» **не меняется**.
2. Защита: действие принимает запросы только с секретом из `config.php` (секрет лежит в свойствах скрипта как `SERVER_SECRET`).
3. `GET` прайса и `onEdit` остаются как есть.
4. Старые действия (`upload`, приём заказа напрямую) оставляю работающими до конца переезда — это путь отката.
5. 👤 Один раз: добавить свойство `SERVER_SECRET` в Свойства скрипта (значение я сгенерирую и покажу).

### Этап 4. Страница приложения (🤖)

1. `index.html` переезжает на hoster.by (тот же код, другой адрес API).
2. Фото отправляются файлом, а не base64; фоновая загрузка по 3 штуки сразу — остаётся.
3. Вариант на GitHub Pages пока не трогаю — он продолжает работать со старым сервером (это и есть откат).

### Этап 5. Проверка до переключения (🤖 + 👤)

1. 🤖 Автотесты против сервера: прайс, загрузка фото, заказ без фото, заказ с 10 фото, табличка без ФИО (должна быть ошибка),
   повторная отправка того же заказа (не должен задвоиться), обрыв на середине загрузки.
2. 👤 Тестовый прогон в Telegram **до** смены адреса у всех: в @BotFather можно создать второе тестовое Mini App
   или временно поменять адрес и сразу вернуть. Сделать 2–3 заказа: с фото, с табличками, большой.
3. Проверить: сообщение в группе, фото в ответе, строка в таблице, ссылка на фото в ячейке «№ заказа», время оформления.

### Этап 6. Переключение (👤, 2 минуты)

1. @BotFather → `/myapps` → приложение → **Edit Web App URL** → `https://<новый адрес>/?v=1`.
2. Если закреплённая кнопка в группе ведёт на `t.me/бот/приложение` — она не меняется. Если в ней прямой адрес
   GitHub — 🤖 перевыпущу кнопку (`postOrderButton`).
3. Предупредить агентов: закрыть и заново открыть Telegram.

### Этап 7. После переключения

1. Первую неделю: 🤖 раз в день смотрю журнал ошибок сервера (если попросишь — по расписанию).
2. Через 1–2 недели без проблем: убираю из Apps Script старые `upload`/приём заказов, GitHub Pages переключаю
   на страницу-заглушку или оставляю как резерв.
3. Обновить `CLAUDE.md`: как выкатывать сервер на hoster.by.
